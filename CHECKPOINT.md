# Чекпоинт 2 — «Корсик»: RAG-ассистент для онбординга (ПОЛИПЛАСТИК)

## Что это
Рабочий MVP в микросервисной архитектуре (Docker). HR загружает регламенты через панель управления → OCR → векторная база →
ИИ-ассистент отвечает новичкам строго по базе знаний, анализирует настроение и передаёт сложные случаи живому HR.

## Адреса
| Что | Адрес | Для кого |
|---|---|---|
| **Панель управления HR** | **http://192.168.110.239:8003** (логин/пароль — `ADMIN_USER`/`ADMIN_PASSWORD` из `.env`) | HR |

Остальные сервисы (gateway :8001, ingest :8002, Qdrant :6333) — только внутри машины.

## Архитектура
```
HR ─► admin :8003 ─► ingest :8002 ─► llm-gateway :8001 ─► OpenRouter (Qwen3-Embedding-8B)
         │            PDF/PPTX → текст (текстовый слой, иначе Tesseract OCR) → чанки → Qdrant :6333
         └─► pipeline :8004 ◄── MAX (long polling / webhook)
              агент: search_knowledge_base · escalate_to_hr ─► llm-gateway ─► Qwen3.8-27B
              sentiment + темы + красные флаги ─► аналитика и эскалации в панели управления
```
Модели и провайдер меняются в `.env` без правок кода (gateway).

## Сценарий демонстрации (≈5 минут)

**1. Загрузка документа (панель управления → «Документы»)**
- Перетащить PDF (например, скан «Правила внутреннего трудового распорядка», 23 стр.).
- Статус «обработка…» → «готово»; в колонке «Стр./чанков/OCR» видно, что страницы распознаны OCR.
- Кнопка «Текст» — показать распознанный текст. *Ключевая мысль: HR сам пополняет базу знаний, без разработчиков.*

**2. Вопросы по базе знаний (бот в MAX)**
- «Сколько длится ежегодный оплачиваемый отпуск?» → 28 календарных дней, ссылка на документ и страницу.
- «Можно ли принимать подарки от поставщиков?» → лимит 3 000 ₽, запрет на деньги (антикоррупционная политика).
- «Во сколько начинается рабочий день и когда обед?»
- **Защита от галлюцинаций:** «Какой пароль от wifi в офисе?» → бот честно говорит, что в базе нет, и предлагает HR. Ничего не выдумывает.

**3. Эскалация и ответ HR**
- В чате: «Мой начальник постоянно кричит на меня, я хочу уволиться» → бот сочувствует и передаёт обращение HR.
- Панель управления → «Эскалации»: новое обращение. Клик по строке → **весь диалог сотрудника**.
- Написать ответ → «Отправить ответ». Бот отправит его в мессенджер.
- Также работает команда `/HR` в чате.

**4. Аналитика (панель управления → «Аналитика»)**
- Тональность сообщений, темы вопросов, доля ответов по базе знаний, красные флаги (токсичность, намерение уволиться и т. п.), открытые эскалации.
- *Это закрывает «предиктивную аналитику» из кейса: HR видит проблемы до увольнения.*


## Что реализовано по кейсу
| Требование кейса | Статус |
|---|---|
| RAG по неструктурированным вопросам | ✅ |
| HR сам загружает PDF/регламенты без кода | ✅ (OCR сканов, PPTX, DOCX) |
| Контроль галлюцинаций | ✅ порог релевантности, «не знаю» + предложение HR, ответы только по найденному |
| Эскалация живому HR | ✅ только по кнопке «Передать HR» (сотрудник подтверждает, что именно уйдёт) + диалог + ответ HR через бота; команды бота правятся в панели управления |
| Sentiment Analysis, красные флаги | ✅ |
| Аналитика для HR | ✅ базовый дашборд |
| Канал MAX | ✅ MAX — бот подключён по токену, long polling, события и приветствие подтверждены вживую; сценарий теста — `MAX_TEST.md` |
| Проактивные рассылки по таймлайну | ✅ 21 этап из ТЗ: планировщик, площадки ГрПП/ГТП/Лужники, «ты/вы», опросы с ветвлениями, напоминания, «отмашка рекрутера» |
| Стиль общения Корсика по регламенту ТЗ | ✅ тексты дословно + промпт нейросети по регламенту (мужской род, тон, эмодзи, границы) |
| Дашборд для руководителей/push-уведомления | ⏳ следующий этап |

## Честно о ограничениях
- MAX: подключение, `bot_started` и отправка проверены; полный диалог с реальными пользователями — по сценарию `MAX_TEST.md`. Для продакшена нужен webhook (HTTPS:443).
- Автотесты (4 сервиса, 100% покрытия строк) работают на моках; сквозной сценарий проверен вручную на реальных документах.
- Ответ модели занимает 10–40 с (модель с рассуждением).
- Авторизация в панели управления — Basic-auth; для продакшена нужны SSO/роли.
- Сценарий рассылок из ТЗ (за 2–3 дня до выхода, 1-й/3-й день, опросы с ветвлением) — на следующем этапе.

## Запуск
```bash
docker compose -f compose.yml -f compose.proxy.yml up -d --build   # эта машина (через прокси)
docker compose up -d --build                                                      # обычный сервер
python scripts/seed.py ПОЛИПЛАСТИК/            # загрузить регламенты скриптом
./scripts/test_all.sh                          # тесты
```
